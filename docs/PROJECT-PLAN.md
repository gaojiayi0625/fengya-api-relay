# 项目实施计划（建议稿）

> 本文用于明确后续开发边界和验收标准，不代表相关功能已经在当前公开仓库中实现。

## 1. 项目目标

蜂芽 AI API 中转站面向需要统一接入多个大模型厂商的团队，目标是减少协议差异带来的接入成本，并为令牌、用量和预算提供统一管理入口。

## 2. 建议的 MVP 范围

首个可验证版本建议聚焦以下闭环：

1. 通过统一入口接收模型请求。
2. 根据模型标识选择上游厂商和模型。
3. 使用平台令牌完成身份校验。
4. 记录请求用量、耗时和结果状态。
5. 返回结构化错误，便于调用方排查。
6. 提供基础额度限制，避免异常消耗。

支付、复杂计费、自动故障转移和管理后台可以在核心转发链路稳定后逐步加入。

## 3. 模块划分

### 接入层

- 接收并校验请求
- 识别协议与模型
- 生成请求追踪标识
- 对错误响应进行统一封装

### 路由层

- 维护模型与上游厂商的映射
- 应用超时、重试和熔断策略
- 避免对不可安全重试的请求重复执行

### 凭据与权限

- 平台令牌只存储不可逆摘要
- 上游密钥通过环境变量或密钥管理服务注入
- 为令牌配置最小权限、额度和失效时间

### 用量与审计

- 记录模型、令牌、耗时、状态和用量
- 日志不得保存完整密钥或敏感请求正文
- 为费用核对和问题追踪保留必要审计字段

### 计费与支付

- 订单创建、支付回调和余额变更相互解耦
- 支付回调必须验签并保证幂等
- 余额变更应保留可审计流水

## 4. 非功能要求

- **安全性**：密钥不进入代码库、日志和公开截图。
- **可靠性**：设置上游超时、有限重试和异常隔离。
- **可观测性**：每个请求具备追踪标识，关键指标可统计。
- **兼容性**：协议差异通过适配层处理，不泄漏到业务层。
- **可维护性**：配置、路由和厂商适配器保持职责分离。

## 5. 验收标准

### 核心链路

- [ ] 有效令牌能够完成一次模型请求。
- [ ] 无效、过期或超额令牌返回明确错误。
- [ ] 不支持的模型不会被错误路由。
- [ ] 上游超时不会导致请求无限等待。
- [ ] 单次请求可以通过追踪标识定位。

### 安全与费用

- [ ] 仓库历史和运行日志中不存在明文密钥。
- [ ] 日志对手机号、订单号和令牌等字段脱敏。
- [ ] 支付回调经过验签和幂等校验。
- [ ] 用量记录与余额变更可以审计。

### 文档与测试

- [ ] 安装、配置和启动步骤可以由新贡献者复现。
- [ ] 关键配置项包含示例和安全说明。
- [ ] 路由、鉴权、额度和错误映射具备自动化测试。
- [ ] 发布前完成最小化端到端验证。

## 6. 建议里程碑

1. **M0：仓库基础**  
   明确范围、安全策略、贡献流程和配置规范。
2. **M1：核心转发**  
   完成单一协议、单一上游的请求闭环。
3. **M2：多模型路由**  
   引入厂商适配器、统一错误和用量记录。
4. **M3：令牌与额度**  
   增加令牌生命周期、额度限制和审计能力。
5. **M4：计费与运营**  
   在安全评审后接入支付、订单和运营监控。

每个里程碑都应以可运行代码、自动化测试和可复现文档为完成条件。
